# 论文结构、算法与数学表达的完整处理方案

适用版本：PaperWeave 0.1.0-alpha.39。本文区分已实现的规则、现有缓存的修复方式和仍需人工复核的边界。

## 目标与原因

输出仍是左侧原页 60%、右侧译文 40%。原始 PDF 始终保留。右侧按正文阅读顺序排版，算法、图表及独立公式保留英文原貌；不把一张完整算法框拆成截图、列表和译文混排。

ReplaySSM 暴露了三个相互关联的问题：

| 问题 | 原因 | 处理位置 |
| --- | --- | --- |
| 算法 1–3 重复、半截，算法 4 变成标题与列表 | 结构接口把同一物理区域拆成表格、正文、标题和列表；旧流程按类型连续分组 | 页面区域识别与排版 |
| `withj≤huse`、`draftssit`、`oneT×Ttriangular` 被当成英文表达 | PDF 字体切换和链接边界的空格在文字提取时丢失 | 文字提取、公式识别、翻译输入 |
| 译文中出现被截断的变量或邻近英文笔画 | 部分行内字形坐标存在误差，调节截图边距仍无法稳定恢复数学对象 | 数学展示与失败回退 |

修改 Prompt 只能辅助翻译，不能修正区域坐标或恢复丢失的文字边界。因此处理贯穿以下流程。

```mermaid
flowchart LR
  A[原始 PDF 与结构信息] --> B[恢复文字和变量边界]
  B --> C[确认完整算法与图表区域]
  C --> D[正文公式保护与本文术语]
  D --> E[逐段翻译并校验对应关系]
  E --> F[修订与保存]
  F --> G[数学分流与 60/40 排版]
  G --> H[检查实际 PDF]
```

## 1. 先恢复可读的原文

- 在压平文字前读取结构接口的字形推进量和字体分段，恢复有证据的词间空格、正文与数学变量的边界。
- 根据同一行中可靠的字号和基线差恢复显式上下标；不对图表内部文字或标题的小型大写字体推测上下标。
- 分开 `Equation 8`、`Algorithm 5` 等编号引用和后面的叙述文字。
- 保留连字、跨行断词、脚注和公式位置的既有保护。字形数量无法与文字一一对应时，不按猜测插入字符。
- 保持原段落 ID、顺序和页码，以便旧译文仍能找到原段落。

例如，送给翻译器的句子应是 `The terms with j≤h use cached corrections`，其中 `j≤h` 是一个数学对象，`with`、`use` 是待翻译的普通叙述。

## 2. 按物理区域保留算法和图表

- 同页相交的表格/算法碎片按坐标合并，即使其间夹着正文或列表节点，也只生成一个完整裁切区域。
- 从 `Algorithm N` 标题识别没有表格节点的算法，再纳入相邻的 Input、Output、编号步骤、return 和提交说明。
- 算法后的解释段落、节标题、其他编号表格是边界，不能因相邻而吞并。
- 对被接口误标为表格的绘图，根据相邻图注恢复其归属；不同栏的图表不因结构顺序而混成同一区域。
- 每个区块在同一页只归属一个区域。只有一个正文区块的全部矩形都在原文区域内时，才停止单独处理它，避免丢掉跨页正文。
- 区域内的文字不参与术语提取和正文翻译，也不重复输出旧译文。原始区块、已有译文及人工修订均保留。
- 手工修改区域类型优先于自动规则，可以把指定内容改为正文后单独翻译。
- 算法、图表和说明作为整体缩放、换页，不裁成上下两半；源文件本来跨页的内容逐源页保留。

ReplaySSM 的目标是：算法 1–3 共享原来的组合框；算法 4 连同九条步骤保留；算法 5 保留完整；算法 6 连同最后的 return 和提交说明保留。

## 3. 公式先保护，再翻译叙述

- 识别完整表达式，包括条件、上下标、维度、函数和省略号。`T×T` 和 `diag(...)` 不能拆成不相干的变量片段。
- 公式与代码先进入不可改写的保护表，再识别和保护本文技术术语，防止重复包装。
- 模型按段翻译，必须保留每个保护对象的数量和身份；丢失、重复或来源不明时停止该段保存，继续保留已有结果。
- Prompt 明确翻译条件前后的普通叙述；在代数上下文中，`terms` 应理解为“项”，而不是自动译为“术语”。
- 模型优先级、Codex/DeepSeek 配置与额度切换沿用原来的设置。

例句可译为：“满足 \(j\le h\) 的项使用已缓存的校正量；满足 \(h<j<t\) 的项涉及较早的草稿，其校正量尚未知。”公式和条件保持不变，普通叙述需要完整翻译。

## 4. 根据证据选择数学展示方式

| 内容 | 右侧展示 | 依据不足时 |
| --- | --- | --- |
| 算法、图表、图注、表格 | 完整原文区域，保持布局与颜色 | 对照左侧原页复核分类 |
| 独立公式 | 原文公式完整区域，保留编号 | 提示复核源区域 |
| 明确的行内变量、显式上下标、关系式、乘积和受支持的函数 | 本机 MathJax 转 LaTeX 矢量路径；公式整体换行，不拉伸内部字距 | 保留完整原文段落并提示复核 |
| 缺少结构证据的矩阵、堆叠分式等 | 不从压平字符猜测结构 | 保留完整原文段落，译文仍可编辑 |
| 用户修订中显式输入的 LaTeX | 优先按用户的公式排版 | 解析失败时报告错误 |

行内数学不再依赖可能偏移的局部 PDF 截图。自动 LaTeX 采用受限语法，并在写入 PDF 前实际解析，不能把 `withj≤huse` 这类混入叙述的字符串当成数学标签。复杂结构不能证明时，需要原文核对或人工 LaTeX；不声称已恢复全部数学结构。

## 5. 修复已有项目

1. 打开原论文或已有生成附件时，从同一原始 PDF 本地更新结构元数据。
2. 核对文库、附件、文件哈希、段落 ID 和规范化源文。整篇不能安全对应时保留旧项目并提示，不强行套用新分段。
3. 可以对应时更新文字边界、数学映射和区域归属，保留已有译文、术语、区块 ID、人工修订、输出记录及原始附件。
4. 检测旧译文中仍保留的粘连源文，或缺少可靠数学对应的段落，标记为需复核。直接重新生成 PDF 不会自动修好这些旧译文。
5. 用户可点击“重译需复核段落（保留人工修订）”。仅处理需复核的自动译文；每段成功返回并校验后再覆盖，失败不清空旧译文，完成部分逐段保存。
6. 人工修订的段落不会被批量重译；可手工修改，或选择“重新翻译本段（覆盖）”。

数学对应或原文修复尚未复核时，PDF 中保留完整原文段落并显示说明；已有中文仍在编辑器中，避免把已知有问题的片段继续拼进新 PDF。

## 6. 使用与验收

安装 alpha.39 并重启 Zotero后，右键打开目标论文，等待本地结构更新。先检查算法分类和“公式 / 格式需复核”筛选，再在“分步操作：词表与翻译”中按需重译。最后点击“翻译并生成 PDF”生成新的阅读附件。

本次离线检查包括：

- 完整类型检查、插件回归、真实 PDF 构建和页面渲染。
- ReplaySSM 的算法 1–6、被圈出的正文、LaTeX 行内表达式，以及独立公式 9–11。
- 25 个本机项目、11051 个区块和 5051 条已有译文的副本检查：原缓存、译文与人工修订未被写入或覆盖；同页区块重复归属为 0。
- 其中 19 个项目可完整对应并迁移；6 个项目不能严格对应，按保护规则保留原结构。这不代表这些项目的提取问题已经修好。
- 新增算法分组、正文边界、跨页保护、手工分类、旧缓存迁移、模型输入、行内 LaTeX、复杂结构回退及浮点相邻边界回归。

ReplaySSM 预览中的四段中文经过本地人工校订，用于展示结构和数学排版；没有调用真实模型，也没有覆盖 Zotero 中的缓存。其他旧译文没有进行全文语义审校。alpha.39 尚未安装到 Zotero 做原生验收，尚未作为社区 Release 发布。

## 仍有的边界

扫描件需要 OCR。结构接口的区域和字体信息可能不完整，自动术语识别与语义翻译仍需复核。当前不是通用的视觉数学 OCR，也不承诺从任意 PDF 自动重建全部 LaTeX。后续若接入视觉识别，应作为可选步骤，显示识别来源与置信信息，并继续保留原式对照，不能静默覆盖人工修订。
