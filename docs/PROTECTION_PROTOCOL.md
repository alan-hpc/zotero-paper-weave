# 翻译保护协议与错误恢复

alpha.31 将公式、LaTeX、行内代码、原文中类似标记的字符串和技术术语纳入同一个扁平保护表，修复先保护公式、再把已有标记当作普通文本保护所造成的嵌套。渲染阶段沿用原文数学对象和可编辑译文项目。

## 根因和复现

alpha.30 的多轮字符串替换可能把 `x=已保护的公式` 整体再次替换成一个新标记。内部标记不再出现在请求正文，却仍列在要求模型复制的清单中。模型复制了清单中的标记后，正向逐个还原也可能留下后展开的内部标记，报「模型产生了未知占位符」。

此问题已在当前 Zero-SM NCCL 项目的 b110、b154、b157 离线复现。复现使用原项目快照和本地模拟响应，没有访问模型服务，也没有修改项目缓存。修复针对整条保护流程，不以段落编号或论文内容作为代码条件。

## 不变量

1. **扁平保护表。** 保护值只能来自原文，不能包含本次请求已生成的标记。后续正则只处理未保护的片段，不能跨过或进入已有标记。
2. **原始坐标合并。** 重叠的数学、代码、LaTeX 和字面标记区域先在原文坐标中合并，再保护一次；公式在区域中的偏移仍保存为身份绑定。源文印出的星号与插件生成的加粗标记分开处理。
3. **逐段隔离。** 标记包含由段落身份和原文计算的 64 位命名空间；每次翻译使用独立注册表。生成前检查命名空间与原文字面内容不冲突。
4. **发送前检查。** 每个注册项在请求正文中恰好出现一次，生成的粗体结构也必须有效。内部错误直接停止，不交给模型反复尝试。
5. **响应先校验。** 每个预期标记恰好出现一次，不能出现未知命名空间、编号或未闭合的保留前缀。
6. **单次还原。** 校验后按响应位置从左到右还原一次，插入的原文永不再次扫描。原文中真的包含 `PWLOCK...` 时可以原样显示，不会被错当作残留协议。

## 可本地修复和必须重试的区别

允许修复标记内部的大小写、全角英数、空白、标点、零宽分隔符和前导零变化；只规范化协议本身，不对整段中文或数学字形做 NFKC 转换。

模型将标记展开为原文时，只在精确字面值和缺失项的出现数量一致、位置没有歧义、不会截取另一个词或已有标记时恢复。无法唯一对应的情况不猜测。

缺失、重复、未知编号、其他段落的标记、截断和损坏前缀进入同一校验路径。每段最多尝试三个响应，重试携带缺失、重复、未知项及上一版草稿；仍失败则返回带段落 ID、分类计数和 `PW_PROTECTION_INVALID` 的错误。错误信息不包含 API 响应体、密钥或完整论文文本。

## 修订和批处理

还原时一起计算粗体、数学引用的最终 UTF-16 偏移，并在清理列表前缀后调整引用。代码/显式 LaTeX 内已有精确来源绑定的内容保留其字面展示，不重复截取一个公式。

批量任务中的保护协议失败只使该段保持待翻译；其余段落继续并逐段保存。完成后列出失败段落，不生成缺段 PDF。再次点击主按钮只处理仍未完成的段落。网络、配置、取消、保存失败及其他错误仍停止新请求，等待已在处理的段落收尾。

已有译文和人工修改不会被批量任务覆盖。显式点击「重新翻译本段（覆盖）」并成功返回后，才更新所选段落；失败不改变该段缓存。现有项目无需清空或整篇重译。

## 验证范围

- 结构回归：多层识别器交叉、公式/代码/LaTeX 重叠、原文字面标记、重复词、Unicode、源文星号、粗体和列表引用偏移。
- 响应回归：七类错误、有限重试、精确展开恢复与歧义拒绝、130 个标记、乱序还原和并行隔离；另有 50 组往返组合。
- 工作台集成：协议失败后继续保存其他段落、禁止生成缺段 PDF、列出失败 ID、只重试未完成段落，以及 HTTP 配置错误停止新任务。
- 本机 15 篇项目、3241 段、18769 个保护值均通过本地回显往返。缓存快照未修改，未请求实际模型。当前 Zero-SM NCCL 的 140 段全部通过保护检查；已保存的 104 段保留，其余段落并未因此自动翻译。

这些检查验证协议和缓存处理，不等于对实际模型翻译质量、任意 PDF 版面或 Zotero 内运行的保证。alpha.31 安装包尚未在 Zotero 内安装验收。
