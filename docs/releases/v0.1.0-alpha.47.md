# PaperWeave 0.1.0-alpha.47 · 修复“译完仍无法生成 PDF”的误判

适用于 Zotero 10，Alpha 预览版，包含 alpha.46 的全部修复。

“已翻译全部段落”只表示译文已有保存。生成前还会核对区域类型、数字和数学表达；未解决的疑问仍会暂停导出。本版修复误分类和格式误报，保留这一步核对。

- 将算法内 kernel 声明、注释、并行循环、编号步骤、赋值及大段表格/数学节点归入完整原文区域，不再当作普通正文反复识别。正文形式的算法标题需有邻近、对齐的 Input/Require 作为依据；人工分类和普通解释段落仍保留。
- 限制算法按下方正文推断栏宽时跨入邻栏，图表四周留白以相邻区域中点为界，避免算法 4 右侧带入别的图文残字。
- `¹⁷`、`_{17}`、`^{17}` 等数字按数值与出现次数核对；不会把 `2¹⁰` 合并成 `210`。重复的 Figure 17 漏掉一次仍会阻止生成，并明确显示缺少的数字。
- 数字或类型不匹配、但模型未报告视觉不确定时，自动带诊断重读原截图一次。仍不确定则保存并停在核对区，不丢失旧译文。该步骤可能增加一次图片请求，仍使用当前模型，不跨服务回退。
- 第 4 版提示要求保留原文语法错误而不据此报告看不清，区分正文粗体小标题与图注，并完整保留脚注及重复图号。旧版未解决的记录会重查，新版待核对记录不无限重复请求，已采用和人工修订的识别继续保留。
- 缓存升级以已采用的识别与对应译文核对数学表达，避免原始抽取仍有歧义就把已解决段落重新标为待复核。状态区显示具体核对原因。

安装并重启 Zotero 后打开原来的 SonicMoE 项目，保留图片识别选项，再点击“翻译并生成 PDF”。已有译文和修订继续复用；如仍有疑问，按新版显示的具体原因核对原图并采用识别结果后继续。无需清空缓存或更新模型代理。

已通过类型检查、完整离线回归、打包及实际图表 PDF 目检。SonicMoE 的 502 个区域在项目副本中升级后，全部 230 段译文和 52 个已采用识别层保留；12 个待核对项中，8 个算法碎片已归入完整原图，其余 4 个保留给新版模型复查。已检查完整算法 1–6、数字格式、真正遗漏的 Figure 17 和相邻裁切；原项目缓存与附件未修改。未调用真实模型，尚未在 Zotero 内安装验证，不声称本篇全部待核对项已经通过模型复查。
